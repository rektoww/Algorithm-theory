
# Виртуальный музей (Virtual Museum)

Консольное приложение на Python для управления виртуальным музеем, учёта взаимодействий посетителей и анализа популярности музейных материалов.

Проект разработан в рамках лабораторной работы №2 «Модули и пакеты Python. ООП» по дисциплине «Теория алгоритмов».

- **Вариант:** №22 — «Виртуальный музей»
- **Уровень сложности:** Well-done
- **Язык программирования:** Python 3.14
- **База данных:** SQLite
- **Контейнеризация:** Docker

## 1. Описание приложения

Виртуальный музей — приложение, позволяющее создавать каталог экспонатов и статей, регистрировать посетителей и учитывать их взаимодействия с музейными материалами.

На основании просмотров, лайков, добавлений в избранное и закладок программа рассчитывает популярность экспонатов и статей, формирует рейтинг материалов и статистику каждого посетителя.

Приложение использует объектно-ориентированный подход и модульную архитектуру. Данные сохраняются в SQLite и автоматически восстанавливаются после повторного запуска программы.

- Добавление статей в закладки

## 4. Объектно-ориентированная архитектура

В основе приложения лежат следующие классы.

### MuseumContent

Абстрактный базовый класс музейного материала.

Содержит общие свойства экспонатов и статей: идентификатор, название, количество просмотров и лайков.

Определяет общий интерфейс расчёта популярности через абстрактный метод `calculate_popularity()`.

### Exhibit

Класс экспоната, наследующий MuseumContent.

Дополнительные свойства:
- Категория экспоната
- Количество добавлений в избранное

Реализует собственный расчёт популярности и метод добавления в избранное.

### Article

Класс статьи, наследующий MuseumContent.

Дополнительные свойства:
- Автор статьи
- Количество добавлений в закладки

Реализует собственный расчёт популярности и метод добавления в закладки.

### Visitor

Класс посетителя музея.

Хранит сведения о просмотренных экспонатах, прочитанных статьях, поставленных лайках, добавлениях в избранное и закладках.

Предоставляет методы для выполнения соответствующих действий.

В проекте используются:
- Наследование классов
- Абстрактные методы и декораторы
- Управляемые атрибуты через `@property` и сеттеры
- Проверка корректности передаваемых данных
- Специальные методы `__init__`, `__str__`, `__repr__`

## 5. Расчёт популярности

Популярность материалов рассчитывается с использованием взвешенной суммы пользовательских действий.

### Для экспонатов

```python
popularity = views + 2 * likes + 3 * favorites
```

### Для статей

```python
popularity = views + 2 * likes + 3 * bookmarks
```

Таким образом:
- Просмотр или прочтение приносит 1 балл
- Лайк приносит 2 балла
- Добавление в избранное или закладки приносит 3 балла

Материалы сортируются по убыванию полученной популярности.

### Статистика посетителя

Программа рассчитывает:
- Общее количество просмотров экспонатов
- Количество уникальных просмотренных экспонатов
- Общее количество прочтений статей
- Количество уникальных прочитанных статей
- Количество поставленных лайков
- Количество добавлений в избранное
- Количество добавлений в закладки
- Общее количество совершённых действий

## 6. Установка и запуск

### Требования

Для локального запуска необходимы:
- Python 3.14
- pip
- Библиотеки из `requirements.txt`

Основные сторонние библиотеки проекта:
- `python-docx` — создание документов Word
- `openpyxl` — создание файлов Excel
- `pytest` — автоматическое тестирование

SQLite используется через встроенный модуль Python `sqlite3` и не требует отдельной установки через pip.

### Запуск в Windows

Откройте терминал в директории `python_lab_02`.

Рекомендуется предварительно создать виртуальное окружение:

```powershell
python -m venv .venv
```

Активируйте окружение в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Запустите приложение:

```powershell
python main.py
```

После запуска откроется интерактивное консольное меню виртуального музея.

Для завершения работы выберите пункт `0`.

## 8. Хранение данных в SQLite

Приложение использует SQLite для постоянного хранения информации.

База содержит три основные таблицы:

| Таблица | Содержание |
|---|---|
| `contents` | Экспонаты, статьи и показатели популярности |
| `visitors` | Зарегистрированные посетители |
| `interactions` | История взаимодействий посетителей с материалами |

Связи между таблицами реализованы с использованием внешних ключей (`FOREIGN KEY`).

Для обеспечения целостности данных используется проверка внешних ключей и транзакционная запись изменений.

При добавлении экспонатов, статей и посетителей ID назначаются SQLite автоматически.

После перезапуска приложения материалы и статистика посетителей восстанавливаются из сохранённых данных.

При локальном запуске файл базы располагается по адресу:

```text
data/museum.db
```

Для просмотра содержимого базы можно использовать DBeaver или другие SQLite-клиенты.

## 9. Запуск через Docker

Проект поддерживает запуск в изолированном Linux-контейнере.

Docker-образ содержит Python, зависимости и исходный код приложения.

### Сборка образа

Перейдите в директорию `python_lab_02` и выполните:

```powershell
docker build -t virtual-museum .
```

### Запуск контейнера

```powershell
docker run --rm -it -v museum-data:/app/data virtual-museum
```

Описание основных аргументов:
- `--rm` — автоматическое удаление контейнера после завершения работы
- `-i` — поддержка интерактивного ввода
- `-t` — создание терминала
- `-v museum-data:/app/data` — подключение постоянного хранилища для SQLite

Docker Volume `museum-data` обеспечивает сохранность базы данных после завершения и удаления контейнера.

### Повторный запуск

Используйте ту же команду:

```powershell
docker run --rm -it -v museum-data:/app/data virtual-museum
```

При повторном запуске данные из `museum-data` будут доступны новому контейнеру.

### Сохранение отчётов на компьютере

По умолчанию отчёты, созданные внутри контейнера, находятся в его файловой системе.

### Пересборка после изменений

Если исходный код или зависимости изменились, пересоберите образ:

```powershell
docker build -t virtual-museum .
```

После этого новый контейнер будет запускаться на основе обновлённого образа.

- Проверка внешних ключей

- Экспорт отчётов Excel

Всего реализовано **25 автоматических тестов**.

### Локальный запуск тестов

Из директории `python_lab_02` выполните:

```powershell
python -m pytest -v tests
```

### Запуск тестов в Docker

```powershell
docker run --rm virtual-museum python -m pytest -v tests
```

Для тестирования SQLite используется фикстура `tmp_path`, предоставляющая отдельную временную директорию для тестовой базы.

Это позволяет выполнять тесты без изменения основной базы данных приложения.

Все 25 тестов успешно пройдены как в локальном окружении, так и внутри Docker-контейнера.
