# Генераторы Python

Лабораторная работа № 4 «Функции-генераторы и работа со встроенными функциями Python» по теории алгоритмов. Вариант № 20.

## Задания варианта 20

1. Выбрать с помощью `random.choice` 1 000 000 нот из `['до', 'ре', 'ми', 'фа', 'соль', 'ля', 'си']` и показать первые 20. Можно задать объём и целое зерно `seed`. Пустое поле выбирает новое зерно, которое приложение показывает в результате.
2. Показать первые 20 целых чисел, кратных 3, начиная поиск от `a = -100`. Первые значения `-99`, `-96`, `-93`, последнее `-42`. Если `a` уже кратно 3, оно входит в результат. Генератор вычисляет значения арифметически, без коллекций.
3. Отобрать корректные email-адреса из строки. В локальной части и каждом сегменте домена разрешены `A–Z`, `a–z`, `0–9` и `_`. Один `@` делит адрес на локальную часть и домен. Домен состоит из двух или более непустых сегментов, разделённых точками. Пробельные символы разделяют адреса. Программа сохраняет порядок и повторы, для каждого отклонённого адреса показывает причину. Это учебное правило варианта 20.

## Установка и запуск на Windows

Команды выполняются из каталога `python_lab_04`. Если в корне репозитория уже есть `.venv` с нужными зависимостями, можно использовать `..\.venv\Scripts\python.exe`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m lab04.main
```

Для PyCharm создайте конфигурацию **Python**. В качестве цели выберите **Module name** и укажите `lab04.main`. Установите **Working directory** в `python_lab_04` и выберите интерпретатор окружения с PyQt6. Точка входа использует `if __name__ == "__main__"` и `freeze_support()` для безопасного старта процессов на Windows.

## Консольный режим

Команды ниже предполагают, что выбран Python из нужного окружения. Для CLI в рабочем режиме достаточно стандартной библиотеки Python.

```powershell
python -m lab04.cli --help
python -m lab04.cli notes --seed 42
python -m lab04.cli notes --count 20 --seed 42
python -m lab04.cli notes --mode parallel --workers 2 --count 1000000 --seed 42
python -m lab04.cli multiples --start -100 --count 20
python -m lab04.cli emails --demo
python -m lab04.cli emails "user_12@dept.example.org bad@@site.ru"
python -m lab04.cli benchmark --scenario standard --workers 2 --seed 42
python -m lab04.cli benchmark --scenario cpu --workers 2 --seed 42
python -m lab04.cli benchmark --mode sequential --scenario cpu --count 100000 --rounds 64
python -m lab04.cli benchmark --mode parallel --scenario cpu --workers 2 --repeats 3
```

В командах с пулом укажите `--workers 1`, если доступен один логический процессор. CLI принимает `--batch-size` от 1 до 16 384. Размер пакета по умолчанию равен 4 096. Для точного повтора укажите одинаковые `--seed`, `--count` и `--batch-size`. В CLI можно остановить вычисление с помощью `Ctrl+C`.

## Как работают генераторы

- `random_notes()` через `yield` выдаёт по одной ноте, используя метод `choice()` собственного экземпляра `random.Random`. `multiples_of_three()` сначала вычисляет `a + (-a % 3)`, затем увеличивает значение на три после каждого `yield`. `islice()` ограничивает число извлечённых значений.
- Последовательный режим обрабатывает пакеты в одном процессе. Параллельный режим использует `ProcessPoolExecutor` с контекстом `spawn`. У каждого пакета свой детерминированный seed. Размер пула ограничен доступными логическими CPU и количеством пакетов. В Windows действует дополнительный предел пула в 61 процесс.
- Оба режима используют одну функцию обработки пакета. В родительский процесс поступают частоты, часть предпросмотра и контрольная сумма. В очереди находится до двух пакетов на процесс. Результаты объединяются в порядке отправки, поэтому совпадают и частоты, и первые 20 нот. Сумма частот проверяется при каждом запуске.
- Фильтрация email использует `filter()` для отбора принятых адресов и генераторные выражения для обхода адресов и частей домена. `any()` проверяет наличие пробельных символов, `all()` проверяет части домена. `map(str, ...)` подготавливает числа к выводу, `zip()` сопоставляет ноты с частотами.
- `QThread` координирует тяжёлую операцию за пределами потока интерфейса Qt. При остановке программа прекращает отправлять пакеты, отменяет доступные для отмены задания и дожидается завершения работы пула. Закрытие окна использует тот же механизм.

## Сравнение производительности

Во вкладке **Производительность** выберите сценарий, задайте число процессов и нажмите **Сравнить производительность**. По умолчанию выполняются один полный прогрев каждого режима и три измеряемых повтора.

| Сценарий | Работа | Параметры по умолчанию |
| --- | --- | --- |
| А · Стандартная | Случайный выбор нот, частоты и первые 20 значений. | 1 000 000 нот |
| Б · Нагрузка SHA-256 | Дополнительно вычисляет цепочку SHA-256 для каждой ноты. На каждом шаге входом служит предыдущий хеш. Контрольная сумма позволяет сравнить результат обработки. | 100 000 нот × 64 итерации. Доступно от 1 до 256 итераций. |

`perf_counter()` измеряет время каждого прохода от подготовки его пакетов до объединения частот. Порядок режимов чередуется. Медиана исключает полный прогрев, создание и закрытие пула. Приложение отдельно показывает время от создания пула до готовности всех процессов. Для оценки одноразового запуска учитывайте и эту подготовку. Вкладка «Генератор нот» показывает полное время разового запуска с созданием и закрытием пула.

Коэффициент ускорения равен `Tпосл / Tпар`. Значение выше 1 означает выигрыш. Экономия в процентах равна `(1 − Tпар / Tпосл) × 100`. Отрицательный процент означает, что параллельный прогон занял больше времени. При одинаковых параметрах бенчмарк сверяет итоги всех проходов, включая контрольную сумму сценария Б.

В обычной сборке CPython глобальная блокировка интерпретатора GIL ограничивает параллельное выполнение Python-кода в потоках одного процесса. У дочерних процессов собственные интерпретаторы, поэтому работу можно распределить по ядрам. Для лёгкой генерации время передачи пакетов и планирования может превысить выигрыш. Для SHA-256 доля вычислений больше, но результат также зависит от доступных ядер, размера пакета, состояния системы и ограничений среды. График показывает результаты текущего запуска.

## Тесты и Docker

Быстрый прогон проверяет генераторы, email, числа, формулы бенчмарка, взаимодействие с PyQt6, остановку и завершение процессов. Длительные проверки выделены маркером `benchmark`. Ни одна проверка не требует достижения заданного ускорения.

```powershell
python -m pytest
python -m pytest -m benchmark
```

Docker запускает CLI и pytest на Python 3.13. Compose ограничивает контейнер двумя CPU и устанавливает число процессов, видимое Python. Для запуска настольного приложения на Windows достаточно PyQt6.

```powershell
docker compose build
docker compose run --rm lab04 notes --mode parallel --workers 2 --count 10000 --seed 42
docker compose run --rm lab04 multiples
docker compose run --rm lab04 emails --demo
docker compose run --rm lab04 benchmark --scenario cpu --workers 2 --seed 42
docker compose run --rm --entrypoint python lab04 -m pytest
docker compose run --rm --entrypoint python lab04 -m pytest -m benchmark
```

В контейнере тесты интерфейса пропускаются, поскольку в образ устанавливаются только консольные зависимости из `requirements-core.txt`.
